## 1. Структура проекта

```
StarterForTrusttunnel/
├── main.py                          # интерфейс и вся логика приложения
├── get_localizations.py             # работа с файлами: чтение, создание, сохранение
├── for_create_localization_file.py  # словари по умолчанию (эталон)
├── style.tcss                       # стили Textual
├── settings.json                    # создаётся сам: путь к папке и имя конфига
└── localization/                    # создаётся сам
    ├── en.json
    ├── ru.json
    └── status.json                  # какой язык выбран сейчас
```

Разделение ответственности между тремя Python-файлами:

| Файл | За что отвечает | Знает ли про диск | Знает ли про интерфейс |
|---|---|---|---|
| `for_create_localization_file.py` | Значения по умолчанию | нет | нет |
| `get_localizations.py` | Чтение/запись JSON | да | нет |
| `main.py` | Интерфейс и логика | нет | да |

Смысл в том, что зависимости идут только в одну сторону: `main.py` → `get_localizations.py` → `for_create_localization_file.py`. Нижние слои ничего не знают о верхних, поэтому их можно тестировать и менять по отдельности.

## 2. Что происходит при старте

Ещё до создания приложения, на уровне модуля, выполняются четыре строки:

```python
l_en = out_en()                  # словарь английских строк
l_ru = out_ru()                  # словарь русских строк
l_ = fws("get")["Status"]        # "english" или "russian"
cl = choise_language(l_)         # активная локализация
```

Порядок важен. `fws("get")` возвращает **словарь** из `status.json` (`{"Status": "english"}`), поэтому нужен `["Status"]`, чтобы достать строку. `choise_language` сравнивает именно строку — если передать туда словарь, он не совпадёт ни с `"english"`, ни с `"russian"`.

> **Историческая справка.** Ровно на этом код и падал: было `l_ = fws("get")` без `["Status"]`, `choise_language` возвращал `None`, и `compose` ловил `TypeError: 'NoneType' object is not subscriptable`.

Дальше:

```python
def __init__(self, *args, **kwargs) -> None:
    super().__init__(*args, **kwargs)
    self.current_lang_name = l_    # "english" / "russian"
    self.current_lang = cl         # словарь строк
```

И `compose` берёт все подписи из `self.current_lang`. Именно поэтому приложение открывается сразу на нужном языке — язык определён **до** того, как построен хоть один виджет.

### Жизненный цикл в Textual

| Метод | Когда вызывается | Что там можно |
|---|---|---|
| `__init__` | при создании объекта | готовить данные; виджетов ещё нет |
| `compose` | при построении экрана | **создавать** виджеты (`yield`) |
| `on_mount` | когда виджеты уже в дереве | `query_one`, менять значения |

Поэтому загрузка настроек в поля ввода живёт в `on_mount`, а не в `compose`: в `compose` виджеты ещё не смонтированы и `query_one` их не найдёт.

## 3. Слой локализации

### Эталон значений

`for_create_localization_file.py` — просто функции, возвращающие словари. Никакого ввода-вывода. Это источник правды: **новый ключ добавляется сюда**, и дальше он разойдётся по файлам автоматически.

### Умное чтение файлов

Вся магия в `_load_json`:

```python
def _load_json(path: Path, defaults: dict) -> dict:
    data = {}
    if path.exists():
        try:
            with open(path, "r", encoding="utf-8") as file:
                loaded = json.load(file)
            if isinstance(loaded, dict):
                data = loaded
        except (json.JSONDecodeError, OSError):
            data = {}          # битый файл -> откатываемся к дефолтам

    merged = {**defaults, **data}
    if merged != data:
        _save_json(path, merged)   # дописываем недостающие ключи
    return merged
```

Ключевая строка — `{**defaults, **data}`. Распаковка идёт слева направо, поэтому:

- значения **из файла** (`data`) перекрывают дефолтные → твои ручные правки переводов выживают;
- ключи, которых **в файле нет**, подтягиваются из дефолтов → старые файлы чинятся сами.

Это и есть механизм миграции. Добавил `"LogsTitle"` в эталон — и у всех пользователей со старым `en.json` ключ появится при следующем запуске. Без этого было бы `KeyError: 'LogsTitle'`.

Плюс защита от битого JSON: если файл повреждён, приложение не падает, а откатывается к значениям по умолчанию.

### Пути от папки скрипта

```python
BASE_DIR = Path(__file__).resolve().parent
LOCALIZATION_DIR = BASE_DIR / "localization"
```

Было `"./localization/en.json"` — путь относительно **текущей рабочей директории**. Запустишь `python StarterForTrusttunnel/main.py` из родительской папки — и приложение создаст вторую папку `localization` не там, где надо, а рядом с тем местом, откуда ты запустил терминал.

`Path(__file__).resolve().parent` — это всегда папка, где лежит сам скрипт, независимо от того, откуда его запустили. `resolve()` заодно разворачивает символические ссылки и относительные пути.

## 4. Сохранение настроек

Цикл из двух половин.

**Сохранение** — по кнопке Confirm:

```python
def confirm_settings(self) -> None:
    folder = self.query_one("#path_to_folder", Input).value.strip().strip('"')
    config = self.query_one("#config_name", Input).value.strip()
    save_settings(folder, config)
    self.notify(self.current_lang["SettingsSaved"])
    self.query_one("#settings_collapsible", Collapsible).collapsed = True
```

`.strip().strip('"')` здесь не случайность. В проводнике Windows «Копировать как путь» кладёт в буфер путь **в кавычках**: `"D:\Trusttunnel"`. Без обрезки кавычек `Path('"D:\\Trusttunnel"')` указывал бы в несуществующее место с кавычкой в имени, и ты бы получил загадочное «файл не найден» при визуально правильном пути.

**Загрузка** — в `on_mount`:

```python
def on_mount(self) -> None:
    settings = get_settings()
    self.query_one("#path_to_folder", Input).value = settings.get("PathToFolder", "")
    self.query_one("#config_name", Input).value = settings.get("ConfigName", "")
```

`.get(key, "")` вместо `[key]` — если файл вдруг окажется неполным, получим пустую строку вместо исключения.

## 5. Запуск процесса

Здесь была главная проблема, и её стоит понять целиком.

### Почему нельзя просто читать вывод

Чтение вывода процесса — **блокирующая** операция: поток встаёт и ждёт следующую строку. Textual крутится в одном event loop, и если запустить чтение прямо в обработчике кнопки, весь интерфейс намертво зависнет: не перерисуется, не отреагирует на клавиши, ничего.

### Решение: рабочий поток

```python
@work(thread=True, exclusive=True, group="tunnel")
def run_tunnel_process(self, exe: Path, config: str) -> None:
    ...
```

Декоратор `@work` из Textual запускает метод в отдельном потоке. Обработчик кнопки вызывает его и **возвращается мгновенно**, интерфейс остаётся живым.

- `thread=True` — обычная функция в потоке (а не корутина);
- `exclusive=True` + `group="tunnel"` — одновременно живёт только один воркер этой группы; если запустить второй, предыдущий отменяется. Защита от двойного запуска.

### Сам запуск

```python
process = subprocess.Popen(
    [str(exe), "-c", config],
    cwd=str(exe.parent),
    stdout=subprocess.PIPE,
    stderr=subprocess.STDOUT,
    stdin=subprocess.DEVNULL,
    text=True,
    encoding="utf-8",
    errors="replace",
    bufsize=1,
    creationflags=creationflags,
)
```

Каждый аргумент решает конкретную проблему:

| Аргумент | Зачем |
|---|---|
| `[str(exe), "-c", config]` | Список, а не строка: аргументы не склеиваются в шелл-строку, пробелы в путях и именах конфигов не ломают команду |
| `cwd=str(exe.parent)` | Процесс стартует из своей папки — относительные пути к конфигам внутри него работают |
| `stdout=PIPE` | Перехватываем вывод вместо печати в консоль |
| `stderr=STDOUT` | Ошибки сливаются в тот же поток. Иначе нужны две трубы и два потока чтения, иначе дедлок при заполнении буфера |
| `stdin=DEVNULL` | У TUI нет консоли для дочернего процесса; если он что-то спросит — без этого зависнет молча |
| `text=True` + `encoding` | Получаем строки, а не байты |
| `errors="replace"` | Кривой байт в выводе не уронит приложение исключением декодирования |
| `bufsize=1` | Построчная буферизация. Без неё Python копит вывод блоками по 4–8 КБ, и логи идут рывками с задержкой |
| `creationflags=CREATE_NO_WINDOW` | На Windows иначе поверх TUI выскочит чёрное окно консоли |

### Чтение вывода

```python
if process.stdout is not None:
    for line in process.stdout:
        self.call_from_thread(self.write_log, line.rstrip())

code = process.wait()
self.process = None
self.call_from_thread(self.set_running_state, False)
self.call_from_thread(self.write_log, f'{l["ProcessExited"]} {code}')
```

`process.stdout` — итератор, который отдаёт строки по мере появления и **сам заканчивается**, когда процесс закрывает поток. То есть цикл живёт ровно столько, сколько живёт туннель. Как только он умер (сам упал или его остановили), цикл выходит, `wait()` забирает код возврата, кнопка возвращается в «Подключиться».

Приятный побочный эффект: если туннель отвалится сам по себе, интерфейс это заметит. Никакого опроса состояния не нужно.

### call_from_thread — обязательно

Мы находимся в **чужом потоке**, и трогать виджеты оттуда напрямую нельзя: Textual не потокобезопасен, получишь гонки и мусор на экране.

```python
self.call_from_thread(self.write_log, line.rstrip())
```

Этот метод ставит вызов в очередь основного потока и выполняет его там. Поэтому **все** обращения к интерфейсу из воркера идут через него: и `write_log`, и `set_running_state`, и `notify`.

Правило простое: внутри `@work(thread=True)` любое касание UI оборачивается в `call_from_thread`.

### Обработка ошибок запуска

```python
except OSError as e:
    if getattr(e, "winerror", None) == 740:
        self.call_from_thread(self.write_log, l["NeedAdmin"])
        ...
```

Код 740 на Windows означает «операция требует повышения прав». Так как мы ушли от `ShellExecuteW("runas")`, процесс наследует права самого приложения. Если `trusttunnel_client.exe` требует администратора — запускай терминал от имени администратора, и приложение унаследует права. Вместо сырого стектрейса пользователь увидит понятное сообщение.

`getattr(e, "winerror", None)` — потому что на Linux и macOS у `OSError` атрибута `winerror` просто нет.

## 6. Остановка и уборка

```python
process.terminate()
try:
    process.wait(timeout=5)
except subprocess.TimeoutExpired:
    process.kill()
```

Вежливо, но настойчиво: сначала сигнал на мягкое завершение (на Windows это `TerminateProcess`), даём 5 секунд закрыть соединения, и только потом убиваем принудительно.

Разница между ними: `terminate()` процесс может перехватить и корректно завершиться, `kill()` — нет, он умирает мгновенно.

```python
def on_unmount(self) -> None:
    process = self.process
    if process is not None and process.poll() is None:
        try:
            process.terminate()
        except OSError:
            pass
```

`on_unmount` срабатывает при закрытии приложения. Без него процесс остался бы висеть в фоне сиротой, и при следующем запуске ты получил бы два туннеля.

`process.poll()` возвращает `None`, если процесс ещё жив, и код возврата, если уже умер. Это неблокирующая проверка, в отличие от `wait()`.

## 7. Логи

```python
RichLog(id="logs", classes="logs", markup=False, highlight=False, wrap=True, max_lines=2000)
```

`RichLog` — виджет-журнал с собственной прокруткой.

- `max_lines=2000` — старые строки отбрасываются, память не течёт при долгой работе туннеля;
- `markup=False` — **важно**: если туннель выведет что-то в квадратных скобках (`[INFO]`, `[2024-01-01]`), Rich попытается прочитать это как разметку и либо съест текст, либо упадёт;
- `highlight=False` — без автоподсветки чисел и путей, вывод остаётся как есть;
- `wrap=True` — длинные строки переносятся, а не обрезаются.

Запись идёт через единственную точку:

```python
def write_log(self, text: str) -> None:
    self.query_one("#logs", RichLog).write(text)
```

Благодаря этому воркеру не нужно ничего знать про устройство интерфейса — он просто просит «запиши строку». Захочешь потом добавить timestamp или писать дубликат в файл — правишь один метод.

Ещё мелочь для удобства: перед запуском и при ошибке блок логов разворачивается сам.

```python
self.query_one("#logs_collapsible", Collapsible).collapsed = False
```

Пользователю не приходится гадать, почему ничего не произошло.

## 8. Переключение языка

```python
def action_choise_lang(self) -> None:
    new_lang_name = "russian" if self.current_lang_name == "english" else "english"
    fws("edit", new_lang_name)                       # 1. записали на диск
    self.current_lang_name = new_lang_name           # 2. обновили состояние
    self.current_lang = choise_language(new_lang_name)
    self.refresh_texts()                             # 3. обновили интерфейс
```

Метод называется `action_choise_lang`, потому что в `BINDINGS` указано действие `choise_lang` — Textual сам ищет метод с префиксом `action_`.

Три шага: сохранить выбор на диск (чтобы пережил перезапуск), обновить состояние в памяти, перерисовать подписи. Виджеты при этом **не пересоздаются** — меняется только текст, поэтому введённые в поля данные и содержимое логов сохраняются.

Два нюанса в `refresh_texts`.

**Первый — надпись на главной кнопке зависит от состояния:**

```python
self.query_one("#start_btn", Button).label = (
    l["ButtonForStop"] if self.tunnel_is_running else l["ButtonForStart"]
)
```

Без этой проверки переключение языка во время работы туннеля откатило бы кнопку на «Подключиться», хотя он запущен.

**Второй — поиск по `id`, а не по типу:**

```python
self.query_one("#settings_collapsible", Collapsible).title = l["SettingsTitle"]
self.query_one("#logs_collapsible", Collapsible).title = l["LogsTitle"]
```

Раньше было `query_one(Collapsible)`, что означает «найди ровно один Collapsible на экране». С появлением второго блока (Logs) это упало бы с `TooManyMatches`. Поэтому у обоих теперь свои id.

Вообще `query_one` — это CSS-селекторы: `#id` — по идентификатору, `.class` — по классу, имя типа — по классу виджета. Второй аргумент (`Button`, `Input`) — это не фильтр, а подсказка типа: он проверяет результат и даёт нормальный автокомплит в IDE.

## 9. Грабли, на которые я наступил

### `is_running` занято фреймворком

```python
self.is_running = False
# AttributeError: property 'is_running' of 'StarterForTrusttunnel' object has no setter
```

У класса `App` в Textual уже есть свойство `is_running` — только для чтения, говорит, запущено ли само приложение. Присваивание в него падает.

Отсюда правило при наследовании от фреймворковых классов: свои атрибуты называй с префиксом предметной области. Поэтому в коде `self.tunnel_is_running`, а не `self.is_running`.

### Жалоба basedpyright на индексацию

```
Argument of type "Literal['Status']" cannot be assigned to parameter "key"
of type "SupportsIndex | slice[...]"
```

Так было, когда `file_with_status` в разных ветках возвращала то `dict` (из `json.load`), то строку `"test"`. Статический анализатор не умеет «заглядывать в будущее» и понимать, что при аргументе `"get"` выполнится именно ветка со словарём. Он собирает общий тип из **всех** `return` — получается `dict | str`, а строку по ключу `"Status"` индексировать нельзя, только числом или срезом.

Лечится приведением функции к одному осмысленному типу возврата. Сейчас `file_with_status` всегда возвращает `dict`, и жалоба ушла сама.

Если когда-нибудь столкнёшься с похожим, есть три способа:

```python
# 1. Подсказать анализатору явно
data = fws("get")
assert isinstance(data, dict)
l_ = data["Status"]

# 2. Заглушить конкретную строку
l_ = fws("get")["Status"]  # type: ignore[index]

# 3. Лучший: сделать так, чтобы функция возвращала один тип
```

### Общий вывод по обоим случаям

И падение с `NoneType`, и претензия анализатора росли из одного корня: функции с `else: pass`, которые молча возвращают `None`, и функции с разнотипными возвратами. Явный возврат одного типа и fallback вместо `pass` избавляют сразу от обоих классов проблем.

## 10. Куда расти дальше

Идеи, если захочешь продолжить:

- **Автозапуск туннеля при старте** — флаг в `settings.json` и вызов `start_tunnel()` в конце `on_mount`.
- **Индикатор статуса в Header** — `self.title` / `self.sub_title` меняются в `set_running_state`.
- **Список конфигов вместо ручного ввода** — просканировать папку на `*.json` и показать `Select` вместо `Input`.
- **Дублирование логов в файл** — одна строчка в `write_log`.
- **Больше языков** — сейчас переключатель жёстко «english ⇄ russian». Чтобы добавить третий, достаточно сделать список языков и переключать по кругу через индекс, а `choise_language` перевести на словарь `{"english": out_en, "russian": out_ru, ...}` вместо цепочки `if/elif`.
- **Автозапуск при старте системы** — ярлык в `shell:startup` на Windows.

Если возьмёшься за что-то из этого и застрянешь — пиши, разберём.
